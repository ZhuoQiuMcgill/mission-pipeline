# WI-13 Unsupported content transform, missing objects, or an unsupported repository format

## Trigger and evidence
- The repository uses a content transform the program does not support; LFS or plain git objects a task needs are missing locally (e.g. a partial clone); an unsupported repository format (unknown extensions, the reftable ref backend, a shallow clone, LFS pointers with extension lines).

## Default action already taken
This task is not dispatched (or this delivery does not run); everything else goes on. Nothing is ever fetched automatically. A reftable repository can be read, dispatched and worked on, but gets no delivery and no landing (v51).

## Options and outcomes
1. The user runs `git lfs fetch` (or completes the partial clone's objects) → the program retries by itself.
2. reftable repository: ask the user to run `git refs migrate --ref-format=files` → deliveries work after the conversion (results stay in the content store meanwhile).
3. Adjust the task to avoid those paths, or the user handles those paths by hand.

## How to choose
Missing objects → 1; reftable → 2; a transform or format that cannot be supported → 3.

## When to ask the user
When the user has to run a command.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
