# WI-02 The target branch is checked out by one external worktree

## Trigger and evidence
- The occupancy is "one", but that one is not the main checkout registered at install: it is an external worktree (often made by Codex or a Claude sub-agent).
- Evidence: worktree path, inferred origin, active processes, last change time.

## Default action already taken
This landing ended before the push and did not land into that worktree (no changing files under an agent's feet); the delivery ref is kept. When that worktree releases the target branch, or after 10 minutes without active processes and changes, the program re-evaluates and tells the PM.

## Options and outcomes
1. Wait (default).
2. The agent is done; allow this one landing into that worktree: `mp land <delivery> --allow-external <worktree>` → when clean, git updates its branch, index and files together; with uncommitted changes the push is refused (WI-06 class B).
3. Deliver the ref only: `mp land <delivery> --deliver-ref-only`.
4. Ask the agent or the user to switch away → zero occupancy: the ref alone moves, by itself.

## How to choose
Active processes → 1 or 3; long idle, a temporary worktree → 2 or 4.

## When to ask the user
Usually not.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
