# WI-02 The target branch is checked out in one worktree that is not clean, or that is external: not landed

The Secretary handles this page.
For an existing escalation, route a PM-class choice with `needs-pm` / `ask-pm` through `mp sec decide <escalation> ...`.
For a question without an escalation, use `mp sec ask-pm "<question>" [--about <notice or item id>]`; the PM answers with `mp pm reply <id> "<text>" [--words W-n]`, visible in `mp sec next` / `mp sec wait`.
The PM decides on recorded words or asks the user under F-3; the PM runs the words-dependent `mp pm` actions below.

## Trigger and evidence

- `mp pm land` found the target branch checked out in exactly one worktree, and that worktree:
  - is **not clean**: uncommitted changes, or an untracked file where the delivery puts one; or
  - is **external**: not the repository's main checkout but another agent's or tool's worktree.
- Evidence: worktree path, inferred origin, last change time, the paths that are not clean. Supported eol/ident conversions count as clean when they give the commit's blob; LF and CRLF alone do not block landing under `core.autocrlf=true`.

## Default action already taken

Nothing was landed: `mp` changes no files over uncommitted work or under an agent's feet. The delivery ref is kept; other work goes on. Nothing retries by itself.

## Options and outcomes

1. Wait until the worktree is clean (its owner commits or cleans the changes), then `mp pm land <delivery> --words W-<n>`.
2. The external agent is done: allow this one landing into its worktree, `mp pm land <delivery> --allow-external <worktree> --words W-<n>` → when it is clean and at the recorded base, git fast-forwards its branch, index and files together.
3. Deliver the ref only: `mp pm land <delivery> --deliver-ref-only` → the user or an agent merges.
4. Ask the agent to switch that worktree away, or send the request through the PM for the user → the branch is checked out nowhere, and `mp pm land` moves only the ref.

## How to choose

The uncommitted work is the user's own → send the facts to the PM, then 1 after they handle it; an active agent → 1 or 3; a long-idle temporary worktree → 2 or 4.

## When to send to the PM

Use the escalation's `ask-pm` option if it has one; otherwise record the question with `mp sec ask-pm "<question>" --about <notice or item id>`. The PM decides on the words or asks the user.
When the uncommitted changes are the user's own (a notice, not a decision).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
