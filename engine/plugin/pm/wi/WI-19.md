# WI-19 The transform description changed after acceptance

The Secretary handles this page.
For an existing escalation, route a PM-class choice with `needs-pm` / `ask-pm` through `mp sec decide <escalation> ...`.
For a question without an escalation, use `mp sec ask-pm "<question>" [--about <notice or item id>]`; the PM answers with `mp pm reply <id> "<text>" [--words W-n]`, visible in `mp sec next` / `mp sec wait`.
The PM decides on recorded words or asks the user under F-3; the PM runs the words-dependent `mp pm` actions below.

## Trigger and evidence

- At delivery, versions in it were verified under another transform description (`core.autocrlf`, `core.eol`, `info/attributes`, ...) than the one in force now.
- Evidence: the versions; which keys or attributes differ, old and new values.

## Default action already taken

No candidate is built and no delivery ref is created; no automatic rebuild (`mp` cannot tell an intended change from a mistake). Other work goes on.

## Options and outcomes

1. Rebuild under the new settings: the versions are materialized again under the new description, re-verified and re-accepted (counted as a delivery rebuild, WI-05; no `mp` command to start it yet) → then deliver again: `mp pm deliver <mission> --outputs ... --words W-<n>`.
2. Ask whoever changed the settings to change them back → once they match, deliver again.

## How to choose

The user changed it on purpose (e.g. told you) → 1; an agent or unknown → `mp sec ask-pm "Was the transform change intentional?" --about <notice id>`, then choose 1 or 2 from the PM's recorded reply.

## When to send to the PM

Use the escalation's `ask-pm` option if it has one; otherwise record the question with `mp sec ask-pm "<question>" --about <notice or item id>`. The PM decides on the words or asks the user.
When you cannot tell whether the change was intended (it is the user's own repository configuration).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
