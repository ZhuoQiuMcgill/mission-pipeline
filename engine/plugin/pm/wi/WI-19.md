# WI-19 The transform description changed after acceptance

## Trigger and evidence
- At landing, the actual transform description (`core.autocrlf`, `core.eol`, `info/attributes`, ...) differs from the one the candidate is bound to. Evidence: which keys or attributes differ, old and new values.

## Default action already taken
This landing ended before the push (WI-06 class A); the delivery ref is kept; no automatic rebuild (the program cannot tell an intended change from a mistake).

## Options and outcomes
1. Rebuild under the new settings: the candidate is re-materialized under the new description, affected objects are re-verified and re-accepted (counted as a delivery rebuild, WI-05) → deliver again with `mp deliver <mission> --outputs ...`.
2. Ask whoever changed it to change it back → once they match, a new landing attempt starts by itself.
3. Deliver the ref only: `mp land <delivery> --deliver-ref-only`; the user merges by hand.

## How to choose
The user changed it on purpose (e.g. told the PM) → 1; an agent or unknown → ask the user whether it was intended, then 1 or 2.

## When to ask the user
When the PM cannot tell whether the change was intended (it is the user's own repository configuration).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
