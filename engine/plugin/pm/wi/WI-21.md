# WI-21 A full run at the end failed

The Secretary handles this page.
For an existing escalation, route a PM-class choice with `needs-pm` / `ask-pm` through `mp sec decide <escalation> ...`.
For a question without an escalation, use `mp sec ask-pm "<question>" [--about <notice or item id>]`; the PM answers with `mp pm reply <id> "<text>" [--words W-n]`, visible in `mp sec next` / `mp sec wait`.
The PM decides on recorded words or asks the user under F-3; the PM runs the words-dependent `mp pm` actions below.

## Trigger and evidence

- A full run of the project's full suite at the end of a mission (`mp pm full-run`, the PM's call: D-7) failed on a clean checkout of the delivery candidate.
- Evidence: the full-run marker (the commit and tree, the environment, each command's exit, the failing commands' output tail, the words or authorization it cites), and the run summary.

## Default action already taken

Nothing is blocked: the marker records the failure honestly, and every later delivery and closing snapshot shows it ("full suite last run … on this tree: failed"). Nothing was repaired, rerun or merged by itself.

## Options and outcomes

1. Repair: send the failure to the PM; it records the user's repair reason: `mp pm repair <mission> --words W-<n> --kind defect --text "<the user's reason, verbatim>" [--about <task-id>]` (name the task the failing output points at) → the Architect reopens the responsible task or adds one (mechanical checks only); once its fix is accepted, `mp pm finish` delivers again; the new tree's status says whether the suite has run on it.
2. Send the choice to the PM to deliver despite the failure: send the failing commands and their consequences; the PM decides the risk under F-3 and obtains delivery consent; on consent, `mp pm finish <mission> --words W-<n>` (or `mp pm land` and `mp pm close` with their words) → it lands with the failure on record; the closing snapshot lists it.
3. Run it again: `mp pm full-run <mission> --words W-<n> --reason "<why another run>"` (or `--authority <item>` when the user left full runs to the PM) → for a failure that looks environmental or flaky (a timeout, a missing service). A failed run is never reused: the suite executes again. A second failure of the same commands means option 1 or 2.

## How to choose

The failing output points at a task of this mission → 1; the failure is outside what the mission changed, or the user has said they accept it → 2; the output points at the environment, not the code → 3, once.

## When to send to the PM

Use the escalation's `ask-pm` option if it has one; otherwise record the question with `mp sec ask-pm "<question>" --about <notice or item id>`. The PM decides on the words or asks the user.
Before option 2 always; delivery consent remains the user's, and the PM decides the risk on words or asks them. Option 1 rests on the user's words: a repair quotes their reason verbatim. Option 3 is a PM full-run decision; send the evidence and reason.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; nothing lands without the user's words; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
