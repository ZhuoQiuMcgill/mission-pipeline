# WI-21 The delivery candidate's closing checks failed

## Trigger and evidence
- Step 5 of delivery re-ran the declared closing checks on the candidate and some failed. Evidence: failed checks and their output, candidate, base.

## Default action already taken
No delivery ref is created; the candidate and the failure evidence are kept; no automatic rebuild (rebuilding unchanged would fail the same way).

## Options and outcomes
1. Generate an integration task to fix the failure on the candidate (through the Secretary; no `mp` command yet: state the choice in the session) → once the fixed version is accepted, the delivery manifest is computed again.
2. Leave the outputs concerned out of this delivery: `mp deliver <mission> --outputs <the other outputs>`.
3. The failure is not this delivery's (the base itself fails): tell the user; per the user's decision deliver the ref only, or wait for the base to be fixed.

## How to choose
The failure is inside the selected outputs' write scope → 1; one output alone causes it → 2; the base itself fails → 3.

## When to ask the user
When the base itself fails and the question is whether to deliver on a failing base.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
