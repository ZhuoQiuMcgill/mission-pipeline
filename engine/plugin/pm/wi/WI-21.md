# WI-21 The delivery candidate's closing checks failed

## Trigger and evidence
- The delivery ran the declared closing checks on a clean checkout of the candidate and some failed.
- Evidence: the failed checks, the run summary (exit codes, the last lines of each failing command), the candidate, the base.

## Default action already taken
No delivery ref is created; the candidate and the run summary are kept; no automatic rebuild (rebuilding unchanged would fail the same way).

## Options and outcomes
1. Fix the failure on the candidate with an integration task (a PM plan batch that asks for it: `mp pm plan submit <mission> --file <plan.json> --words W-<n>`) → once the fixed version is accepted, deliver again.
2. Leave the outputs concerned out of this delivery: `mp pm deliver <mission> --outputs <the other outputs> --words W-<n>`.
3. The failure is not this delivery's (the base itself fails): tell the user; per their decision, wait for the base to be fixed, or deliver the ref only.

## How to choose
The failure is inside the selected outputs' write scope → 1; one output alone causes it → 2; the base itself fails → 3.

## When to ask the user
When the base itself fails and the question is whether to deliver on a failing base.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
