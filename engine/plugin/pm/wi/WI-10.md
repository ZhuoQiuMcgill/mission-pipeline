# WI-10 Resource block, resource watermarks and space reminders

## Trigger and evidence
- Admission beyond the whole machine's capacity (resource block); free disk space or inodes below the watermark; a large-disk task without fuse2fs; a landing's space reminder.
- Evidence: live capacity, reservations, watermarks, units concerned.

## Default action already taken
Resource block: progress is saved, other runnable work goes on. Below the watermark: dispatch pauses and reclamation runs. Space reminders only inform; they block nothing.

## Options and outcomes
1. Add capacity or free space (the user does it) → the work continues by itself.
2. Have the Architect split the task (through the Secretary; no `mp` command yet: state the choice in the session).
3. Install fuse2fs, then the program retries by itself (Ubuntu: `sudo apt install fuse2fs`; needs administrator rights).
4. Wait for units in flight to end (waits that can end happen automatically anyway).

## How to choose
A one-off large task → split it; a machine that is always short → add capacity; only fuse2fs missing → install it.

## When to ask the user
When capacity, space or administrator rights are needed.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
