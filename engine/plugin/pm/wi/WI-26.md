# WI-26 A decision-layer step cannot continue as it is

## Trigger and evidence
- A decision-layer step (Calibrator ①, the Architect's decomposition or feasibility review, Calibrator ②) ended in a state `mp` must not repair by itself; typically a stop covered it, so its hand-back was not accepted or it was not offered again (never while the stop holds).
- Evidence: the step, its dispatch and state, the stop.

## Default action already taken
Only this plan step waits. The rest of the mission (tasks of an earlier effective plan, explorations) goes on within the stop's scope. Nothing restarts by itself.

## Options and outcomes
1. The stop was meant (the user stopped this work): leave it → the plan stays where it is until the user wants to continue.
2. The stop is released and the work should go on: submit a new PM plan batch (the same plan is fine): `mp pm plan submit <mission> --file <plan.json> --words W-<n>` → the decision layer runs again from Calibrator ①; accepted work is not redone; loop counts are kept per PM plan version.
3. The stop is still in force but too wide: narrow it with the user (`mp pm stop-narrow <stop> --scope ...`), then 2.

## How to choose
The user said stop → 1 until the user says otherwise; a stop that was too wide (e.g. "no network" also caught this seat) → 3.

## When to ask the user
Always before resuming work the user stopped (the stop is the user's).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
