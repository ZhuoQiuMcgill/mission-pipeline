# WI-08 An automatic loop is exhausted

## Trigger and evidence
- A loop of a lineage reached its 6.5 limit (including delivery rebuilds and landing attempts), or the same failure signature came twice in a row (no progress; not for delivery rebuilds).
- Evidence: loop, count, each failure signature.

## Default action already taken
Only this lineage stops at "exhausted"; the rest of the mission goes on; the PM is told.

## Options and outcomes
1. The Secretary grants one extra round (at most 2 attempts, with a reason) (through the Secretary; no `mp` command yet: state the choice in the session).
2. Have the Architect split the task or change approach (through the Secretary; no `mp` command yet: state the choice in the session) → the new lineage inherits the old one's counts.
3. Give the task up; it goes on the risk list.
4. After the Secretary has granted once, relay the user's decision to add more: `mp grant <lineage> <loop> --extra <n> --reason "<the user's words>"` → only the user can add more.

### Explorations (8.2 stops 2 and 3, 6.5 no progress)
- Trigger: the round budget is used, a fatal finding of the same class was not fixed in two consecutive rounds, or two rounds ended with the same unresolved findings and nothing new. Evidence: the hand-off document named in the notice.
- Default: no further round is queued for this exploration; an escalation went to the Secretary.
- Options (the Secretary picks; the user when asked, `mp answer <mission> <escalation> --option ...`): `grant` 1 or 2 more rounds; `accept-risk` (the current version with its unresolved findings as residual risks); `send-back` with new direction; `replan` (settles as "no conclusion"; a direction decision: ask the user); `abandon`.
- A seat asked for more evidence runs in one turn than allowed (default 3): recorded as not run; the seat resumes and must hand back.
- Choose: findings shrinking round by round → grant; the same fatal class keeps coming back, or no progress → send-back or replan, not more rounds; acceptable remaining risks → accept-risk.

## How to choose
Same failure signature → change approach rather than add attempts; environment failures → check the environment first (WI-10, WI-18).

## When to ask the user
After the Secretary has granted once.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
