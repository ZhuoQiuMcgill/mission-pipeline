# WI-05 The target branch moved: the delivery candidate is rebuilt on a new base

## Trigger and evidence
- At delivery, or at `mp pm land`, the target branch is no longer at the base the candidate was built and proven on (someone added commits). `mp` lands only a fast-forward from that base and never merges.
- Evidence: the old and the new base.

## Default action already taken
Nothing was merged or landed. The candidate is rebuilt on the new base: the manifest and the proof check run again (no command runs at a delivery). Every rebuild counts (at most 3 per delivery); at the limit the delivery is "exhausted" (WI-08). A delivery ref already made is kept. A rebuilt candidate whose content changed needs re-acceptance first (WI-07).

## Options and outcomes
1. Let it rebuild (default, up to the limit), then land the new delivery: `mp pm land <delivery> --words W-<n>`. After `mp pm finish`, run the same `mp pm finish` again: it lands the rebuilt delivery and closes.
2. Deliver the ref only: `mp pm land <delivery> --deliver-ref-only` → no more rebuilds; the user or an agent merges the candidate with the new base.
3. After exhaustion (WI-08): the Secretary may grant once (at most 2 rebuilds); more only by the user: `mp pm grant <lineage> delivery-rebuild --extra <n> --words W-<n>`.

## How to choose
The branch was only briefly busy → 1; it keeps moving (several agents merging) → land when it is quiet, or 2 early.

## When to ask the user
After the Secretary has granted once (WI-08).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
