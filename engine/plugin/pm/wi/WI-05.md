# WI-05 The base of a delivery candidate keeps moving (delivery rebuilds)

## Trigger and evidence
- Before the delivery ref is created, or when a landing's lease expired, the target branch is no longer the candidate's base (someone merged commits); the candidate must be rebuilt on the new base.
- Evidence: each old and new base.

## Default action already taken
Before each rebuild the program waits until the target branch is quiet (no new commit for 5 minutes); waiting is not counted; after an hour without quiet it tells the PM and keeps waiting. Every rebuild actually run counts against the limit (3 per delivery); others moving the base is not this delivery's fault (no no-progress detection). At the limit the delivery is "exhausted": WI-08. A delivery ref already made is kept.

## Options and outcomes
1. Rebuild after quiet (default, up to the limit).
2. Lengthen the quiet period (e.g. 30 minutes) → later rebuilds are less often wasted, the delivery comes later (no `mp` command yet: tell the maintainer).
3. Deliver the ref only: `mp land <delivery> --deliver-ref-only` → no more rebuilds; the user or an agent merges the current candidate with the new base.
4. After exhaustion, WI-08: the Secretary grants once (at most 2 rebuilds); more only by the user (`mp grant <lineage> delivery-rebuild --extra <n> --reason "<the user's words>"`).

## How to choose
The target is only briefly busy → 1; frequent merges for a long time (several agents in parallel) → 2, or early 3.

## When to ask the user
After the Secretary has granted once (WI-08).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
