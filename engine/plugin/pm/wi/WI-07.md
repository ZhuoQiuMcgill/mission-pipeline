# WI-07 A selected object's content changed on the candidate

## Trigger and evidence
- The delivery's proof check finds that a selected module's write-scope content identity differs from the accepted version (6.6 step 4).

## Default action already taken
A new product version is registered and re-verification and re-acceptance are scheduled; until then the object can only be delivered as "not fully proven".

## Options and outcomes
1. Wait for re-acceptance (default).
2. Deliver now, marked not fully proven → it goes on the risk list.
3. Leave the object out of this delivery: `mp deliver <mission> --outputs <the other outputs>`.

## How to choose
Usually wait; when the user urgently needs the other outputs, 3.

## When to ask the user
Usually not.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
