# WI-03 An external worktree or branch overlaps a mission's write scope

## Trigger and evidence
- A periodic or pre-landing scan finds an external worktree or branch that changed, relative to the base, paths inside the write scope of a module of a mission in flight (committed or not).
- Evidence: worktree, branch, overlapping paths, inferred origin.

## Default action already taken
Nothing is merged or adopted; the pipeline goes on. External work is seen only once it enters the target branch, as the new base: changes inside a write scope register new product versions and re-acceptance, conflicts become integration tasks. Snapshots are made from commits only; uncommitted external content is never read.

## Options and outcomes
1. Do not merge (default) → each side goes on; merging later may bring integration tasks or re-acceptance, at extra cost.
2. Adopt: register that branch's changes as an external result and review it against the mission's requirement items and acceptance standards (through the Secretary; no `mp` command yet: state the choice in the session) → if it passes it can be delivered as proven; if not, it goes on the risk list. The review cost counts against the mission.
3. Steer the pipeline around it: have the Architect adjust write scopes or order of tasks in flight (through the Secretary; no `mp` command yet: state the choice in the session) → fewer conflicts, possibly a later delivery.
4. Ask for the external work to be merged into the target branch first → the pipeline continues on the new base; affected products are re-accepted.

## How to choose
The external work is the user's own, in the same direction → 2 or 4; an experiment or half-done → 1; a large overlap with tasks not started yet → 3.

## When to ask the user
When the external work may contradict what the user said (3.2 class 3), or when the work to adopt is the user's own.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
