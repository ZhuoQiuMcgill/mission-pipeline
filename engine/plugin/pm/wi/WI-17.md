# WI-17 An asynchronous evidence run refused, or the resume state missing

## Trigger and evidence
- A seat asked for an asynchronous evidence run while its session state exceeded the card's resume-state limit; or at resumption the resume state was missing or damaged. Evidence: size and limit; the hash of the missing or damaged state.

## Default action already taken
Over the limit: the asynchronous run is not accepted; the seat hands back this round first or runs synchronously (a second time in one exploration, the PM is told). Missing or damaged: a new session starts with the material the ledger holds; the degradation is recorded.

## Options and outcomes
1. Raise the card's resume-state limit (through the Secretary; no `mp` command yet: state the choice in the session) → later evidence runs can be asynchronous.
2. Split the exploration into shorter rounds (through the Secretary; no `mp` command yet: state the choice in the session).
3. Accept synchronous runs → same results, lower resource use efficiency.
4. Resume state missing while this round relies on a long chain of reasoning: redo the round from the start (counted as an exploration round).

## How to choose
Slightly over → 1; the session is too long anyway → 2; occasional → 3.

## When to ask the user
Usually not.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
