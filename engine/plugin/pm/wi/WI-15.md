# WI-15 A failed attempt: environment failure, resource overrun, seat failure, quarantine

## Trigger and evidence
- **Environment failure** (proof reconciliation found no proof; the three acceptance checks failed; a host ended after 10 minutes of storage fault; caught by an out-of-memory kill): the unaccepted result is quarantined and the program re-dispatches by itself, counted (3 per class, 6 in total).
- **Resource overrun** (the unit's own oom count above 0; an export above its limit): not re-dispatched automatically; "needs disposition".
- **Seat failure** (a failed or malformed hand-back; `.git` in an export): "needs disposition".
- **Quarantine** (refused at the pre-publication check; a result arriving after cancellation or revocation): recorded without effect; "needs disposition"; refused because of a stop → never restarted.

## Default action already taken
Environment failures are re-dispatched and counted; the rest go to the Secretary.

## Options and outcomes
1. Restart (counted) (through the Secretary; no `mp` command yet: state the choice in the session).
2. Raise the resource declaration or export limit and re-dispatch (through the Secretary; no `mp` command yet: state the choice in the session).
3. Check the environment first (the same environment failure repeating: see WI-10, WI-18).
4. Give up; it goes on the risk list; when the attempts are used up, WI-08.

### Explorations
When the task given up was an exploration's author, attacker or interpreter, the exploration stops at that turn. To go on, record the exploration ruling `retry` (the same turn queued again in the same lineage); to end it, `stop` (no `mp` command yet: state the choice in the session).

## How to choose
Resource overrun → raise the declaration or split, never retry unchanged; quarantine from a scheduler handover → a restart is usually enough; the same environment failure again and again → check the environment.

## When to ask the user
Usually not.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
