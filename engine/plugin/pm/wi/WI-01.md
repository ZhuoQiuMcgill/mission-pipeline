# WI-01 The target branch is checked out in several worktrees, or held by a rebase or bisect: not landed

## Trigger and evidence
- `mp pm land` found the target branch:
  - **checked out in several worktrees** (made by bypassing git's protection: `git worktree add --force`, `--ignore-other-worktrees`); or
  - **held by an operation**: a rebase or bisect in progress in some worktree holds the target branch.
- Evidence: each worktree's HEAD, `head-name` in `rebase-merge`/`rebase-apply`, `BISECT_START`.

## Default action already taken
Nothing was landed and nothing was written to git; the delivery ref is kept; other work goes on. Nothing retries by itself: `mp read status` shows the delivery as "delivered, not landed" until it is landed or delivered as a ref only.

## Options and outcomes
1. Wait, then land again once the occupancy clears: `mp pm land <delivery> --words W-<n>` → it lands when the branch is checked out in at most one clean worktree.
2. Detach an abandoned duplicate checkout (only for "several"): `mp pm detach-duplicate <worktree>` → HEAD is detached at the same commit; index and files (uncommitted, untracked and ignored ones included) are unchanged; nothing is deleted; `git switch <branch>` undoes it. Then 1.
3. Deliver the ref only: `mp pm land <delivery> --deliver-ref-only` → no landing; the user or an agent merges; layer 1 shows "delivered, not landed".
4. Ask the occupant (the user or that agent) to finish the operation or switch away, then 1.

## How to choose
There is no "land into one of the several": with several checkouts git picks which one it updates. The occupant is an active agent, or the user is rebasing or bisecting → 4 or 3; a duplicate is clearly abandoned (no recent changes, an agent's temporary worktree) → 2; the delivery is urgent → 3.

## When to ask the user
When the user's own worktree would be detached; when the user must finish their own rebase or bisect (a notice, not a decision).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
