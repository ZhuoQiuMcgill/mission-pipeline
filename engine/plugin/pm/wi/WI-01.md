# WI-01 The target branch's occupancy does not allow an automatic landing (several checkouts, or an operation in progress)

## Trigger and evidence
- When the landing view is built, or at the re-check before the push, the target branch is:
  - **checked out in several places**: by more than one registered worktree (made by bypassing git's protection: `git worktree add --force`, `--ignore-other-worktrees`);
  - **in an operation**: a rebase or bisect in progress in some worktree holds the target branch.
- Evidence: each worktree's HEAD, `head-name` in `rebase-merge`/`rebase-apply`, `BISECT_START`.
- An occupancy that differs at the re-check before the push also ends the attempt before the push (WI-06 class A).

## Default action already taken
This landing attempt ended before the push and wrote nothing; the delivery ref is kept; other work goes on. The program re-checks whenever the target branch or a worktree changes, at least every 10 minutes; when the occupancy becomes zero or one, it starts a new landing attempt by itself and tells the PM. Waiting is not counted and costs no model fees.

## Options and outcomes
1. Wait (default): nobody is interrupted → the delivery waits until the occupancy clears.
2. Detach an abandoned duplicate checkout (only for "several"): `mp detach-duplicate <worktree>` → HEAD is detached at the same commit; index and files (including uncommitted, untracked and ignored ones) are unchanged; nothing is deleted; `git switch <branch>` undoes it; with one occupant left the landing proceeds by itself. The program and the PM never remove a worktree or delete a file.
3. Deliver the ref only: `mp land <delivery> --deliver-ref-only` → no landing; the user or an agent merges; layer 1 shows "delivered, not landed".
4. Ask the occupant to finish the operation or switch away (the user or that agent does it) → the landing then proceeds by itself.

## How to choose
There is no "land into one of the several": with several checkouts git itself picks which one it updates. The occupant is an active agent, or the user is rebasing or bisecting → 1 or 3; some duplicate is clearly abandoned (no active process, no recent changes, an agent's temporary worktree) → 2; the delivery is urgent → 3.

## When to ask the user
When the user's own worktree would be detached; when the user must finish their own rebase or bisect (a notice, not a decision).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
