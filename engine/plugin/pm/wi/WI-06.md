# WI-06 A landing did not complete (A / B / base moved / C)

## Trigger and evidence
Classified in order, the first match wins; "landed" means only that the target branch contains the delivery commit:
- **A, ended before the push**: sparse checkout or `skip-worktree`; authorization refused; not enough space or inodes; occupancy not allowed (WI-01, WI-02); a change found at the re-check before the push; transform description changed (WI-19); a filter outside the allow list (WI-13); attribute-only changes; no controlled view on this platform; the delivery is not current; the base moved (WI-05). Nothing was written.
- **B, safe to retry**: the target is still the base, and the approved worktree meets the "safe to retry" test (e.g. refused because of uncommitted changes or a same-named untracked file).
- **Base moved**: someone moved the target branch to a commit that does not contain the delivery commit.
- **C, everything else**: the check fails the test, leftover lock files, incomplete records.
- Evidence: class, target branch value, refusal reason, check report.

## Default action already taken
A: a new attempt starts by itself when the condition clears (at most once every 10 minutes per delivery, not counted); low space also reminds per WI-10. B: a new attempt starts by itself after the worktree or target changes. Base moved: rebuild per WI-05. C: **the push is never redone automatically**; changed worktrees go to WI-04. At most 4 attempts that reach the push stage per delivery; when used up, WI-08. A stop that refuses the authorization ends the landing with no retry; after the stop is released, land again per the user's earlier "deliver" (unless the user withdrew the delivery).

## Options and outcomes
1. Wait for the automatic new attempt (default for A and B).
2. Deliver the ref only: `mp land <delivery> --deliver-ref-only` → the user or an agent merges.
3. After the user or agent cleared the obstacle (committed or cleaned uncommitted changes, freed space), start a new attempt now: `mp land <delivery>` → attempts that end before the push are not counted; those reaching the push count against the limit. Refused twice for the same reason: find the cause, or choose 2.
4. Attribute-only delivery, or no controlled view on this platform: give the user or agent the manual merge (and re-materialization) commands from the notice.
5. C with only a leftover lock file: the program and the PM never delete it; tell the occupant where the lock is and its likely source; once it is gone, the program starts a new attempt (counted).

## How to choose
The obstacle is an agent's temporary state → 1; it is the user's own uncommitted work → tell the user, then 3 after they handle it; it keeps failing → 2; only a lock file → 5.

## When to ask the user
When the uncommitted changes are the user's own (a notice); when a C-class changed worktree is the user's (as WI-04); when the attempts are used up and the Secretary already granted once (WI-08).

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no repository hooks or forced rewrites in the user's worktrees; no deletion of the user's data.
