# WI-06 A landing did not complete, or a landing intent is left open (A / in progress / B / C)

## Trigger and evidence
"Landed" means only that the target ref is at the delivery commit D. `mp pm land` records an intent (branch, base B, D, the worktree it uses) before git runs, runs git with no database lock held, and judges the result only by the target ref. A later call that finds an intent without a result checks it. Classes, first match wins:
- **A, ended before git ran**: a stop covers the landing; the delivery is not current; the occupancy does not allow it (WI-01, WI-02); the base moved (WI-05). Nothing was written.
- **In progress**: another `mp` holds the landing lock: "landing in progress"; nothing is touched.
- **B, intent open, target ref at B**: git did not take effect, or a git command started by an `mp` that has ended may still be running. "At B" never closes the intent.
- **C, everything else**: the target ref is neither B nor D; HEAD changed between the check and the fast-forward; a git lock file (`index.lock`, the ref's `.lock`) is present.
- A landing that had started before a stop is reported "started before the stop", with what actually happened.
- Evidence: class, the target ref's value, B and D, the worktree, lock files found.

## Default action already taken
A: the delivery ref is kept. In progress: nothing. B: the intent stays open; nothing retries by itself. C: **git is never run again automatically**; a changed worktree goes to WI-04. A call that finds the ref at D records the landing done, without a second update. Other work goes on.

## Options and outcomes
1. A: clear the cause (per the WI named), then `mp pm land <delivery> --words W-<n>`.
2. In progress: wait, then `mp read status`.
3. B, retry: `mp pm land <delivery> --words W-<n>` → reissues the same B→D under the landing lock (compare-and-swap, or the checked fast-forward in the worktree), so a late finish of the old git command and the retry cannot both apply: only D can land. In a worktree it needs the worktree clean, HEAD at B and no git lock file; otherwise it is C. A retry is checked against stops like a new landing.
4. Close the intent as not landed, after a fresh check (`mp read show delivery <delivery>`): `mp pm land <delivery> --close-not-landed` → the delivery ref stays; a later landing starts a new intent. Only you close an intent; `mp` never does.
5. Deliver the ref only: `mp pm land <delivery> --deliver-ref-only` → the user or an agent merges.
6. A leftover git lock file: never delete it; tell its owner where it is and its likely source; once it is gone, 3.

## How to choose
B with a clean worktree at B → 3; B again for the same reason → find the cause, or 5; C → read the evidence, then 4 and 5, or 4 and a new landing (never redo a landing blindly); only a lock file → 6.

## When to ask the user
When the worktree is the user's own (uncommitted changes, someone running git in it), or when C left the target branch somewhere the user did not expect.

The safety floor is never an option: stops stay in force; nothing unproven is called proven; no forced rewrites (reset, forced checkout) in the user's worktrees; no deletion of the user's data.
