## 二、实现与设计文字的差异（实现更严，设计文字待同步）

来自 git 与交付的实现者（代码审查 r1 修复之后）：

- **配置视图**：单个文件的只读挂载不等于冻结路径（从别的挂载命名空间改名文件，挂载就脱离原路径；代码审查 r1 第 1 条，致命）。实现改为：公共 git 目录的路径在命名空间里是一个私有 tmpfs，内放 `config`、`config.worktree`、`info/`、`hooks` 与定位文件的副本，其余条目是指向按描述符绑定的真实目录的链接；`HEAD` 经链接保持实时。工作区根部 `.git` 的覆盖只是第二道防线。
- **钩子**：必须先 `cd "$GIT_WORK_TREE"`（接收端在 git 目录里启动它，`ls-files` 只列当前目录下的路径，否则 `skip-worktree` 检查会悄悄失效；测试发现）。
- **grafts**：`GIT_GRAFT_FILE=/dev/null` 会让每条解析提交的命令打印弃用提示，另加 `-c advice.graftFileDeprecated=false`；视图隐藏 `info/grafts`（本地推送会清掉接收端的这个环境变量），钩子里再导出一次。
- **WI-01**：用 `git update-ref --no-deref HEAD <c> <c>`（以那个工作区自己的定位）实现，效果同 `switch --detach`，但不碰索引、不运行过滤器。已知窗口：所有者恰在 git 取得 HEAD 的锁之前切到同一提交上的另一个分支，被游离的就是那个分支（可撤回）。
- 视图强制 `core.splitIndex=false`；生成器加 `--porcelain` 与 `-c mission-pipeline.landing=<token>`（用于恢复）；竞态特征的恢复命令带上 v47/v48 的参数；落地尝试的账本特征必须唯一，否则两个相同特征会触发无进展规则。

## 四、实现中定下的取舍（发布后再改进）

- **延续判断目前一律转整份审查**：账本要求延续判断的四份清单等于求值器合并后的输入，而判断由席位宿主（`src/seat/results.ts` 的 `judgmentRecord`）按卡片与席位引用的证据生成，所以凡是继承 J₀ 输入的延续判断都会被拒、转整份审查。结果正确，只是多花一次审查。改进：席位宿主在交回之前向求值器取 `continuation` 的答复，按 `merged` 生成四份清单（需要宿主能连到求值器的查询接口）。
- **求值器故障或受阻时，延续判断的采信等待**：不占资源，下一次发布后重新对账；不直接转整份审查（维护者的发布裁定之后，按调度实现者的建议定下）。
- 调度的轻微项：`'superseded'` 处理没有调度层面的测试；看护服务 `stop()` 的账本一步仍把任何退出当作成功；重启时每个已采信的派发任务各查一次待定结果；任务作者需要提供 `TaskSpec.changedLines`；测试夹具里有一个未使用的导出。
- git 与交付 r2 第 7 条（一般）：最终引用创建失败的出口仍没有 WI 告知。
- git 与交付 r2 第 8 条（一般）：现有测试还不能证明它声称的全部保证（目录移动与终止的组合、硬链接回退竞态、峰值资源等）。
- 调度 r1 第 14 条（一般）：`src/scheduler/admission.ts:76、94`：资源准入只看第一块盘，等待分类过窄。
- 调度 r1 第 15 条（一般）：`src/scheduler/scheduler.ts:392`、`main.ts:28`：生产入口未接上 LFS 检查和外部扫描。
- 调度 r1 第 16 条（一般）：`src/scheduler/scheduler.ts:531`：普通异常没有 WI。
- 调度 r1 第 17 条（一般）：`src/scheduler/notices.ts:55、75`：告警复制失败后被游标永久跳过。
- 调度 r1 第 18 条（一般）：`test/scheduler-dispatch.test.ts:92`、`scheduler-queue.test.ts:16`：测试遗漏关键边界，部分预期还掩盖缺陷。
- 调度 r1 第 19 条（轻微）：`src/scheduler/alerts.ts:102`：确定的告警冲突被永远重试。

## 五、实现比设计文字更严的地方（git 与交付 r2 之后）

- 钩子从不让 git 按名字写获准工作区的索引：在私有副本上工作，发布时经 git 自己的锁并在绑定的 git 目录里改名，锁或索引变了就拒绝；索引是链接时判为不落地。
- 核对与恢复命令的谓词覆盖每个已跟踪文件、按内容比较；有隐藏标志或程序复现不了的过滤器时判"无法判断"。
- 准入：每个被重写的文件都按新 inode 计，另计日志目录与对象分散目录。
- 引用写入者：先持久记下目标目录身份与引用名；锁的身份记录之后才算是自己的锁；文件系统不支持硬链接时不创建引用（WI-13）。
- 已知残余：落地自己的钩子在持有 `index.lock` 时被强制结束会留下锁（归 C、WI-06，不自动删除）；接收端经被换成链接的 `refs/heads` 目录写引用的路径未处理；写入者在创建锁与记录锁之间死亡留下的锁无法证明是自己的，保留（WI-14）。
