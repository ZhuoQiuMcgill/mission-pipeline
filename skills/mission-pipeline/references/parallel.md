# Parallel execution — reviewed scopes

Architect maps actual producer, input, file-write and dependency relationships; PM owns authorized scheduling choices. Independent Constructor/Crititor/Stabilizer seats receive the current original authority, task/admission and actual immutable inputs.

Tasks in a wave must have disjoint write scopes unless a declared sequential owner handles their integration. Use exact reviewed write paths or isolated task worktrees; do not give model roles unrestricted host filesystem access in managed mode. `work.write` uses the expected current file hash, so concurrent edits cannot silently overwrite one another.

The first wave exists at root activation. Later `wave.open` operations require prior integration and calibration. `wave.integrate`, like task consumption, rechecks current acceptance, verification and affected barriers. A task-cell ALIGNED does not reset an aggregate-wave ratchet. Unrelated scopes can proceed while a mandatory case is screened.

Long controlled execution runs outside the journal writer lock, with finite leases, heartbeat and deadline. Read-only queries do not mutate schema or publish views. Publication renders outside the lock and rechecks epoch/sequence before replacing a view. Do not delete a worktree until its authorized integration and delivered artifacts are preserved.

A shared seam needs actual end-to-end verification through its declared real producers, not two unrelated mock successes. A valid stage-specific mission may hand off later work to a named authorized owner; it must not silently omit a goal its own principal actually required.
